# 百人の迷宮 正式版 設計書

## 1. 現状分析

### このゲームの本質的な面白さ

1. **百人を分ける判断**:帯の仕切りで隊を割り、どこに何人を送るかを決める。危険を分散するか、集中させるか。
2. **運が手札に変わっていく手応え**:序盤は「？」と不運に振り回される。層を下るほど経験・見込み・装備・加護・名声がそろい、運を抑え込めるようになる。
3. **名もない一人が英雄になる物語**:百人のうち誰かが偶然から覚醒し、名声を集め、予言に選ばれて主を討つ。

### 提供すべき感情

- 暗い迷宮に百人を送り込む **緊張**
- 扉の向こうから誰が戻ってくるかを待つ **祈り**
- 覚醒や大物の宝に出会う **高揚**
- 仲間を失う **喪失**(ただし重くしすぎず、次の判断につながる)
- 手塩にかけた一人が主を討つ **報われる感覚**
- 終盤、見込みが読めて判断が冴えてくる **指揮官としての成長**

### プロトタイプ感の出どころ

| 領域 | 問題 |
|---|---|
| 世界観 | 『百人の私』の夜の画面を流用しただけで、「迷宮」「降りていく」「松明」という場所の感覚がない。地下一層と九層が同じ見た目 |
| 冒険者 | 同じ形の駒が格子に並んだ表計算のような見た目。番号しかなく、誰が誰か覚えられない。英雄の物語が立ち上がらない |
| 判断の画面 | 帯・格子・カードが別々の部品で、「隊を扉に振り分ける」という行為が身体的に感じられない。色付きの格子とカードの対応を目で追う必要がある |
| 結果の演出 | 格子の上に文字が浮くだけ。扉の向こうへ行って戻ってくる、という時間の流れがない。死が数字でしか伝わらない |
| 野営 | 汎用のモーダルに部品を詰め込んだ入力フォーム。休息の場面に見えない |
| 決戦 | 文字とHPバーとボタンだけ。主の姿がない。予言は輪が格子を巡るだけで、勇者が前に出る瞬間がない |
| 遷移 | 層の移動が黒幕に文字だけ。深く潜っている実感がない |
| 音 | 電子的な短い効果音だけで、環境音や音楽がない。迷宮の空気がない |
| 導線 | 加護・名声・予言・見込み・傷など仕組みが多いのに、手引きも手記もない。設定・中断・放棄・記録画面がない |
| 品質 | 保存の版管理がない、エラー時の復帰がない、音量設定がない、動きを減らす設定がない |

### 残すもの / 再設計するもの

- **残す**:ゲームのルールと数値(`dsim.js` / `ddata.js`)、帯と仕切りによる振り分け操作、見込みの表示、結果のまとめ方、保存の仕組み、書体の組み合わせ(Yuji Syuku と Zen Old Mincho)
- **再設計**:画面構成すべて、冒険者の表現、舞台(背景・扉・光)、結果・野営・決戦・降下の演出、音、メニューと手記、設定、初回の手引き

### 不足している機能

設定(音量・演出速度・動きを減らす)、メニュー(中断・放棄)、指揮官の手記(操作と仕組み・図鑑・記録)、歴代の勇者の記録、初回の手引き、セーブの版管理と移行、エラー時の復帰。

### 技術的な制約とリスク

- 静的ホスティングのみ、外部アセットは Google Fonts だけ。画像・音声はすべてコードで生成する(Canvas と Web Audio)
- 百人の小さな人物を毎フレーム描くため、スプライトの事前描画とキャッシュが必須
- スマホ幅(360px)で、扉・人物・帯・カードを一画面に収める情報設計が最大の難所
- ルール部分は変えない。バランス検証ボットの勝率が変わらないことで確認する

## 2. デザインの方向性(4案)

### A. 墨と金の戦記絵巻

- **見た目**:縦に長い巻物を下へ繰りながら遠征が描かれる。冒険者は墨の人影、宝と英雄だけ金泥
- **体験**:物語を読み進める感覚。結果は絵巻の一段として書き足される
- **素材**:和紙、墨のにじみ、金箔。背景は余白
- **動きと音**:筆が走る描画、紙をめくる音、琴と鈴
- **長所**:『百人の私』と地続きの個性。作るのが比較的楽
- **短所**:迷宮の暗さ・閉塞感・危険が出ない。帯で隊を割る操作が絵巻と噛み合わず、判断の画面が文字だらけになる
- **コスト**:中

### B. 指揮官の作戦卓

- **見た目**:上から見た作戦卓。羊皮紙の地図、真鍮の物差し、刻印入りの駒が百個
- **体験**:冷静な司令官として盤面を読む
- **素材**:革、真鍮、羊皮紙、蝋燭の光
- **動きと音**:駒を滑らせる音、物差しのカチッという感触、地図に印を付ける
- **長所**:判断に必要な情報が最も読みやすい。帯の操作と相性が良い
- **短所**:冒険者が駒になり、英雄への愛着が薄れる。扉の向こうの怖さがない
- **コスト**:中

### C. 松明の石室(断面のジオラマ)

- **見た目**:迷宮の一室を断面で見せる。奥の壁に扉が2〜3枚、手前に松明に照らされた百人。深く潜るほど光が細り、色が冷える
- **体験**:隊を割ると、冒険者が実際にそれぞれの扉の前へ歩いていく。「進め」で扉の闇に消え、生き残りだけが出てくる
- **素材**:石積み、苔、鉄の扉、炎の光と闇
- **動きと音**:松明のゆらぎ、塵、扉の軋み、扉の向こうの戦いの音、戻ってくる足音
- **長所**:振り分けが身体的になり、ルールと演出が一致する。降下と喪失を最も強く感じられる
- **短所**:Canvas の作り込みが重い。百人の可読性と描画負荷に工夫がいる
- **コスト**:大

### D. 1ビットのドット絵

- **見た目**:白黒2色の精密なドット絵。人物は8×8ドット
- **体験**:レトロで読みやすい
- **長所**:統一感を出しやすく、描画が軽い
- **短所**:ありふれたインディーの見た目になり、これまでの墨と和の個性を捨てることになる
- **コスト**:中

### 比較

| 観点 | A 絵巻 | B 作戦卓 | C 石室 | D ドット |
|---|---|---|---|---|
| 題材との調和 | △ | ○ | ◎ | ○ |
| 判断のしやすさ | △ | ◎ | ○ | ○ |
| 没入感と緊張 | ○ | △ | ◎ | ○ |
| 英雄への愛着 | ◎ | △ | ○ | △ |
| 独自性 | ○ | ○ | ◎ | △ |
| 開発コスト | 中 | 中 | 大 | 中 |

### 推奨:C を土台に、B の精度と A の物語を統合した「松明の戦記」

- **土台は C**:振り分けを「扉へ歩く」動きにすることで、ゲームの核の操作と演出を一致させる
- **B から**:帯を真鍮の物差しとして作り直し、見込みは扉の下の銘板に刻む。判断の精度を落とさない
- **A から**:冒険者に名前と外見を与え、一人ひとりの戦記(ログ)を残す。結末は戦記の巻物として見せ、歴代の勇者を手記に刻む

## 3. 最終デザイン仕様

### アート

- **配色**:闇 `#0d0b09`、石 `#2a2420`、炎 `#f2a64a`→`#ffd28a`、血 `#c8463c`、加護 `#ffe6a8`。扉の色は紋章色の 朱 `#d9643f` / 藍 `#4f8fc4` / 緑青 `#5fae8f`
- **深度による変化**:1〜3層は琥珀、4〜6層は苔むした黄土、7〜9層は青紫の冷気、最深部は深紅。松明の光量も層ごとに少しずつ減らす
- **人物**:外見は id から決まり(外套の色、頭の被り物、髪)、装備(剣・斧・槍・弓・鎧)と状態(傷の包帯、覚醒の炎の輪、名声の小旗)が絵に出る。事前描画してキャッシュする
- **書体**:見出し・刻印は Yuji Syuku、本文は Zen Old Mincho、数字は等幅

### 画面構成(スマホ基準、PCは横に広げる)

1. 上部:層の深度計(十の刻み+主)、層の名、隊の人数、加護の炎、メニュー
2. 舞台(Canvas):石室、扉、松明、隊。扉は下の銘板と同じ列に並ぶ
3. 隊列の物差し:強さ順の棒グラフと仕切り。並び替えボタン
4. 扉の銘板:部屋の名、人数、見込み。押すと全員をその扉へ
5. 主ボタン「進め」

### 演出とその目的

| 場面 | 演出 | 目的 |
|---|---|---|
| 仕切りを動かす | 冒険者が担当の扉の前へ歩き、物差しがカチッと鳴る | 振り分けを身体的に感じさせる |
| 進め | 扉が開き、隊が闇に入る。扉の向こうから戦いの音 | 待つ緊張を作る |
| 結果 | 生き残りが扉から出てくる。戻らなかった者の数だけ扉の前に小さな灯がともる。覚醒は光の柱 | 喪失と高揚を、数字ではなく出来事として伝える |
| 降下 | 石の層が上へ流れ、刻印された層の名が浮かぶ。光の色が変わる | 深く潜っている実感 |
| 野営 | 焚き火を囲む隊、火の粉、静かな音楽 | 緊張を緩め、判断に集中させる |
| 決戦 | 主の巨大な姿、合ごとの攻防、必殺の予兆で画面が暗くなる | 最後の山場を作る |
| 予言 | 天井から光が隊の上を巡り、一人に落ちる。勇者が前に出て一撃 | 物語の主人公が決まる瞬間を最大に演出する |
| 結末 | 勇者の戦記を巻物として表示し、歴代の勇者に刻む | 報われる感覚と、次の挑戦への動機 |

演出を入れない場面:見込みの数字(即座に更新)、物差しの操作中(遅延なし)、結果カードの文字(読める速度で一度に出す)。

### 音

- **環境音**:風の唸り、水滴、遠い地鳴り(層が深いほど低く、まばらに)
- **音楽**:迷宮では低い持続音の上に、五音音階の琴のような撥弦がまばらに鳴る。野営は焚き火の音と穏やかな旋律。決戦は太鼓の鼓動が主の体力に合わせて速くなる
- **効果音**:扉の軋み、戦いのざわめき、倒れた者を告げる鐘(重なりすぎないよう間引く)、覚醒の鈴の和音、加護の巻き戻し、勝利と敗北の短い曲
- **設定**:音楽と効果音の音量を別々に調整できる

### UI/UX

- **表紙**:迷宮の門と松明の舞台。挑む/続きから/指揮官の手記/設定
- **メニュー**(遊んでいる途中):手記、設定、表紙へ戻る(保存される)、遠征を諦める
- **指揮官の手記**:心得(操作と仕組み)、見聞(入った部屋の記録)、覚醒、主、記録と歴代の勇者
- **初回の手引き**:最初の部屋で、物差しと扉の使い方を短く一度だけ示す。部屋ごとの効果は教えない(遊んで見つける方針は維持)
- **設定**:音楽・効果音の音量、演出の速さ(標準/速い)、動きを減らす(OSの設定に従う)

### 品質

- 保存に版番号を付け、旧版(v1)の遠征はそのまま続けられるように移行する
- 予期しないエラーが起きたら知らせ、保存から再開できるようにする
- 描画は人物を事前描画してキャッシュし、動きがない間は描画を止める
- 横長・縦長どちらの画面でも崩れないようにする

## 4. 実装計画

| 優先 | 対象 | 解決策 | 主なファイル | 完了条件 |
|---|---|---|---|---|
| 1 | 冒険者の個性 | 名前と外見を id から生成。旧セーブにも補う | `dsim.js`, `names.js` | 名前が結果・手記・結末に出る。バランス検証の勝率が変わらない |
| 1 | 舞台の描画基盤 | 石室・扉・松明・人物を Canvas で描く。人物は事前描画してキャッシュ | `art.js`, `stage.js` | スマホとPCで扉と隊が読める。60fps近くで動く |
| 1 | 振り分けと結果の演出 | 扉への移動、入室、帰還、灯 | `stage.js`, `dmain.js` | 仕切りに追従して人物が動く。結果と演出が一致する |
| 2 | 画面構成とUI部品 | 深度計、物差し、銘板、ボタン、パネル | `index.html`, `dungeon.css`, `ui.js` | 一画面で判断できる。押せる領域は44px以上 |
| 2 | 野営・降下・決戦・結末 | 焚き火の場面、降下の遷移、主の絵、予言の光、戦記の巻物 | `stage.js`, `art.js`, `dmain.js` | 決戦まで通しで遊べる |
| 3 | 音 | 環境音・音楽・効果音、音量 | `sound.js` | 場面ごとに音が切り替わる。音量が保存される |
| 3 | メニュー・手記・手引き・設定 | 各画面を作る | `dmain.js`, `ui.js` | すべてのボタンが動く。未実装のボタンがない |
| 4 | 品質 | 版管理と移行、エラー時の復帰、動きを減らす設定 | `store.js`, `dmain.js` | 旧セーブで再開できる。エラー時に案内が出る |
| 4 | QA | 通しプレイ(スマホ/PC)、『百人の私』の回帰、バランス、描画負荷 | `tools/` | すべて問題なし |
